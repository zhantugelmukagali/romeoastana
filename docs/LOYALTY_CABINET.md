# Кабинет бонусов и обновление интерфейса

Главная страница /admin теперь показывает программу лояльности, а не очередь
возвратов. Данные реальны: журнал PostgreSQL, резервы и справочник клиентов
подключённого аккаунта МойСклад. При отсутствии операций отображается пустое
состояние. Демонстрационные покупки и балансы не добавляются.

## Где находится функциональность

- Обзор: текущие бонусы у клиентов, число участников, начисления и списания,
  резерв, правила и последние подтверждённые операции.
- Клиенты: поиск по имени/телефону в МойСклад, баланс/доступно/резерв,
  карточка клиента и история. Просмотр не создаёт бонусный счёт.
- Операции: полный журнал с загрузкой следующих страниц без повторов.
- Виджет заказа: расчёт доступного списания, резерв, применение скидки,
  подтверждение после сохранения. Списание из кабинета без заказа не добавлено.
- Настройки: правила, подготовка виджета, перенос остатков и запуск программы.
- Возвраты и сверка: административный разбор исключений.
- /returns: сохранён доступ к прежней очереди возвратов.

Начисления по-прежнему выполняет фоновый обработчик после подтверждения полной
оплаты и отгрузки. Интерфейс кабинета не заменяет его запуск.

Общий светлый интерфейс содержит боковую навигацию, компактные таблицы, карточки,
доступные состояния загрузки/ошибки и мобильную раскладку. Скрипты и стили
доставляются с собственного домена; внешние шрифты и аналитика не добавлены.

## Безопасность и данные

Новые endpoints /api/admin/overview, /customers, /customers/{id}, /activity
доступны только серверно подтверждённому администратору. Чтение не изменяет
финансовый журнал. Балансы вычисляются из проводок и активных резервов с tenant
фильтрами и RLS. Итоги программы передаются десятичными строками, чтобы большие
суммы не теряли точность в JavaScript.

Клиенты читаются только с фиксированного REMAP endpoint, 25 за страницу,
с проверкой accountId, типа и уникальности UUID. Поиск передаётся параметром,
а не частью URL пути/SQL. API возвращает только нужные поля. Имена и телефоны
рендерятся через textContent. Журнал использует курсор created_at/id и проверяет
принадлежность курсора аккаунту/выбранному клиенту.

Полный дескриптор marketplace/descriptor-widget.xml открывает /admin и объявляет
виджеты заказов. Изменения файлов на VPS сами по себе не добавляют виджет в
установленную конфигурацию МойСклад.

## Совместимость и обновление

Текущий совместимый выпуск использует схему0015; основная ветка —0017. Персональные скидки включаются отдельно и не меняют прежние заказы.
0014 добавляет защищённую смену покупателя до финансовых операций и отдельный
неизменяемый аудит. Существующие проводки, остатки и зафиксированные правила
сохраняются. Основную ветку нельзя подставлять вместо совместимого образа.

В ветке bonuspro/vendor-auth-fix deploy/finish_release.py последовательно
обновляет приложение, обработчик и проверяет реальные документы без записи.
При переходе0013/0014→0015 deploy/update_cabinet.py собирает образ из чистых
исходников, создаёт защищённые копии конфигурации, ключей и БД, проверяет
восстановление и точную миграцию в отдельной базе. На время обновления
останавливает HTTPS, app и worker. Новый app проверяется локально до доступа
пользователей. Возврат к0013 разрешён только до открытия доступа и при пустом
новом аудите. После открытия доступа автоматического отката схемы нет.
Финансовая рабочая БД из копии автоматически не восстанавливается.

Для уже установленной0015 обновление образа сохраняет прежнюю конфигурацию и
откатывает app при неуспешной проверке. Затем start_processing.py запускает
обработчик тем же образом и ждёт нового результата; releasecheck проверяет
метаданные и ограниченную выборку реальных заказов. Ключи не перевыпускаются,
программа не активируется и граница начислений не меняется.

Скрипт запускают с sudo из отдельно обновлённого worktree; он не выбирает
ветку и не выполняет git pull. Порядок приёмки и ограничения: HANDOVER.md.

## Проверки

Добавлены PostgreSQL/API проверки сумм, резервов, пагинации, изоляции tenant,
прав и отсутствия финансовых изменений при просмотре; проверки REMAP справочника
и возврата старой конфигурации при неудачном обновлении; Chromium сценарии
обзора, поиска, карточки клиента, защиты от HTML-инъекции, мобильной ширины,
онбординга и доступа по ролям.

Chromium создаёт desktop/mobile скриншоты с синтетическими тестовыми данными.
Они сохраняются в артефакте bonuspro-interface задания browser.
Они подтверждают состояние тестируемого интерфейса, не приёмку реальной продажи.

Рабочие продажи по-прежнему требуют установленного полного дескриптора,
подготовки программы, запуска обработчика и сценариев из ACCEPTANCE.md.
