## Подготовка отдельного каталога на VPS

Выполнять в SSH-сеансе под ubuntu. Старый /home/ubuntu/romeoastana и контейнеры
romeo-customer не менять. Эта подготовка не запускает новую систему и не переключает домен.

```bash
git clone --branch bonuspro/rebuild --single-branch https://github.com/zhantugelmukagali/romeoastana.git ~/bonuspro-release &&
cd ~/bonuspro-release &&
cp -n deploy/moysklad.public.env .env.release &&
sudo python3 deploy/prepare_secrets.py
```

Если каталог уже существует, clone остановится: не удалять его и не перезаписывать
секреты. Сначала проверить имеющуюся установку.

sudo запрашивает пароль Ubuntu, а затем скрипт отдельно выводит
`MoySklad Vendor Secret (hidden):`. Только на этом втором запросе вставить
Secret Key из кабинета. Ввод не отображается. Не передавать ключ аргументом команды,
не выводить файлы секретов через cat.

Скрипт создаёт ключ шифрования и отдельные пароли новой БД, сохраняет секреты
в deploy/secrets с ограниченными правами. Повторный запуск отказывается
перезаписывать существующие секреты. Это скрипт первой установки, не ротации.
Нужна независимая зашифрованная резервная копия секретов перед запуском.

## Следующий этап

Собрать и проверить новую версию, указать BONUSPRO_IMAGE в .env.release.
Для Compose использовать --env-file .env.release -f compose.release.yaml.
Сначала отдельная БД, bootstrap и миграции; только после проверки — маршрутизация HTTPS.
Самостоятельно запускать старый compose.yaml с новыми секретами нельзя.

До реальной установки проверить, что в сохранённом в кабинете дескрипторе используются
те же origin, /admin и user-context, что и в marketplace/descriptor-draft.xml.
Учетные данные сами по себе не подтверждают содержимое дескриптора.

Выпуск по-прежнему блокируют задачи из [IMPLEMENTATION.md](IMPLEMENTATION.md),
включая виджет списания, автоматическую обработку документов и завершение настройки.
