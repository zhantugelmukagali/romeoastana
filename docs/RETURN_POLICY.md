# Возвраты без отрицательного баланса

Подтверждено заказчиком 13.10.2026: недостаток бонусов при отмене начисления
разбирает администратор; автоматический отрицательный баланс запрещён.

Реализовано в Returns и миграции 0003:
- Каждая отмена привязана к исходному начислению и UUID документа возврата.
- При достаточном свободном остатке — отдельная компенсирующая проводка.
- Если остатка не хватает или уже есть нерешённое дело — pending, без списания.
- Pending блокирует новые резервы. Существующие резервы сохраняются:
  скидка могла уже попасть в МойСклад и должна быть сверена.
- Администратор может отменить начисление при достаточном остатке либо
  простить списание (waived), указав причину. История не редактируется.
- Повтор документа/решения идемпотентен; изменение суммы того же документа
  требует отдельной сверки, а не повторного автоматического списания.
- Все возвраты, включая waived, учитываются в лимите исходного начисления.
- PostgreSQL проверяет связи, переходы, баланс и изоляцию магазинов.

Граница готовности: это проверенный внутренний финансовый сервис. Его суммы
должен вычислять доверенный адаптер МойСклад по актуальным документам. Публичного
метода передачи произвольной суммы возврата нет. Интерфейс администратора и
автоматическая сверка документов ещё не подключены. Возврат ранее списанных
бонусов — отдельный сценарий, этой отменой начисления не заменяется.
