# Часть 1: правила и расчёт

Миграция 0006 добавляет rule_versions, customer_wallets и order_contexts:
FORCE RLS, составные внешние ключи, запрет изменения/удаления истории.
API настроек только для подтверждённого администратора с проверкой Origin.

GET /api/admin/rules — текущая версия или null, без неявного создания настроек.
PUT /api/admin/rules — проценты в basis points (500 = 5%), expected_version,
UUID request_id и обязательная причина. Автор и магазин берутся из сессии.
Конфликт версии возвращает 409; повтор того же request_id с тем же телом возвращает
исходный результат, другой payload отклоняется. Доставка: только exclude.
GET /api/admin/rules/history — 50 версий, пагинация по version.
Страница /settings открывается из МойСклад; ссылка добавлена в /admin.

Внутренний Checkout.preview принимает OrderSnapshot от будущего доверенного
адаптера. Публичного API, принимающего клиентские суммы или wallet_id, нет.
eligible_minor должен вычисляться сервером по товарным позициям, исключая доставку,
с тем же eligibility_version, который зафиксирован в заказе.
Конфликт версии требует повторной классификации по правилам заказа.

Счёт определяется UUID контрагента в аккаунте; совпадение телефона или имени
само по себе никогда не объединяет балансы. Полный импорт и слияние дублей — отдельно.
При первом расчёте сохраняется версия правил и клиент. Изменение клиента блокирует
дальнейший расчёт до отдельной процедуры согласования.
Оплаченные, отгруженные, отменённые и не-KZT заказы не допускаются к новому списанию.
Предварительный расчёт НЕ резервирует и НЕ списывает средства.
quote_hash — идентификатор содержания расчёта, не криптографическое разрешение
на списание. Перед резервом и записью требуется повторная проверка документов.
Правила магазина пока сериализуют подготовку заказов в рамках магазина; нагрузочное
тестирование и оптимизация блокировок обязательны перед масштабированием.

На VPS работает предыдущая схема 0005. Не выполнять только миграцию:
старая версия приложения специально отклоняет несовпадение схемы.
Выкатка 0006 требует резервной копии, нового образа и согласованного обновления.
Эта часть не включает виджет списания, реальную классификацию документов или Activated.
