# Остатки, запуск и сотрудники

Схемы 0010–0013; код проверяется на PostgreSQL, настоящая установка ещё не принята.

## Перенос остатков

Раздел /migration доступен администратору из настроек.
Формат UTF-8 CSV: counterparty_id,bonus_balance; допустим также разделитель ;.
Один пакет: до 100 строк и 60 КБ. UUID — контрагент данного аккаунта МойСклад.
Баланс — целое неотрицательное число; дроби, формулы, дубли, лишние колонки отвергаются.
Формат исходного экспорта БонусПлюс ещё не получен; его нельзя считать автоматически поддержанным.
До загрузки нужно явно сопоставить клиентов. Совпадение имени не является основанием для слияния.

Предпросмотр перечитывает клиентов REMAP, отвергает архивных, сохраняет строки/имена,
контрольную сумму, поколение установки и итог. Ничего не начисляет.
Предпросмотр действует 24 часа; после истечения нужен новый.
Подтверждение содержит только ID предпросмотра, digest и причину. Суммы берутся с сервера.
Пакет фиксируется целиком одной транзакцией; одна ошибка отменяет все его начисления.
Уникальность opening_balances по tenant/counterparty не позволяет повторить клиента другим пакетом.
Повтор того же подтверждения с тем же автором/причиной возвращает результат.
Счёт должен быть без прошлых операций и резервов. Нулевые остатки учитываются без нулевых проводок.
Импорт разрешён только в SettingsRequired до создания automation_config.
Автоматического отката уже принятого пакета нет: подтверждение требует сверки исходной ведомости.

## Активация

Администратор сохраняет правила, готовит поле виджета, завершает перенос,
подтверждает сверку и отсутствие обработки новых покупок прежней программой.
Кнопка «Запустить программу» сохраняет intent с request ID, автором, поколением установки,
версией правил и UUID поля. Далее сервер сообщает Activated в Vendor API.
Только подтверждённый HTTP 200 позволяет отдельной lifecycle-роли включить установку,
сохранить completion и создать дату начала/курсор одной транзакцией.
Сетевого запроса внутри финансовой транзакции нет.

Потерянный ответ оставляет локальное SettingsRequired: повтор с тем же request ID безопасен.
Suspend/Uninstall/смена поколения во время запроса не перезаписываются активацией.
Изменённые правила требуют нового подтверждения. Повтор успешной команды не сдвигает начало.
Возобновление установки не меняет уже существующий cutoff и не допускает повторный начальный импорт.
Создание конфигурации не запускает контейнер worker: эксплуатационный запуск отдельный.
Тесты не активировали реальный аккаунт заказчика.

Официальный контракт: https://dev.moysklad.ru/doc/api/vendor/1.0/#rest-endpointy-na-storone-moegosklada

## Сотрудники

Раздел /staff. Сотрудник появляется после подтверждённого Vendor user context.
Логин берётся из userUid провайдера, не из формы браузера.
По умолчанию не-администратору запрещены бонусные операции.
Администратор явно разрешает доступ **к заказам и бонусам всего данного аккаунта**.
Это не имитация детальных ограничений МойСклад на отдельные документы.
Само сохранение заказа по-прежнему выполняет host под правами сотрудника.

Изменение разрешения содержит причину, автора, версию и уникальную команду.
Конкурентные изменения защищены версией. Перед подготовкой/подтверждением списания
права повторно проверяются под тем же lock, который используется отзывом.
Разрешение оператора никогда не открывает административные API.
Сессия администратора ограничена 15 минутами; изменение его роли в МойСклад
отражается при новом обмене контекстом, а Suspend/Uninstall отзывает всё поколение сессий.

## Подготовка реальной приёмки

1. Обновить сервер согласованным релизом после backup и проверки восстановления.
2. Обновить дескриптор виджета в кабинете и проверить установку на аккаунте разработчика.
3. Пройти покупку со списанием, оплатой, отгрузкой и возвратом; затем повтор/отмену/два сотрудника.
4. Сверить фактический экспорт БонусПлюс и контрольные остатки.
5. Проверить worker, нагрузку, оповещения и резервирование VPS.
6. Только после приёмки назначить момент перехода магазина.
