# Эксплуатация БонусПро на VPS

Приложение, PostgreSQL и пул обработки работают на VPS. Открытый браузер, SSH и ноутбук для обработки не нужны. Docker и четыре контейнера запускаются автоматически.

Операционный пакет добавляет внешние копии, проверку восстановления и Telegram-мониторинг. Установка не активирует магазин, не меняет правила, бонусные проводки или ключи приложения.

## Подготовка владельца

1. **Отдельное S3-хранилище.** Закрытый bucket вне основного VPS. Нужны HTTPS endpoint, регион, bucket, Access Key ID и Secret Access Key. Ограничьте доступ папкой копий: PutObject, GetObject и ListBucket для этой папки. Удаление и создание bucket не нужны. Основной VPS в роли S3 не является независимым хранилищем.
2. **Telegram-бот.** Откройте @BotFather, отправьте /newbot, создайте отдельного бота для БонусПро. Сохраните токен в менеджере паролей. Откройте бота и нажмите Start. Установщик запросит токен скрытым вводом и сможет найти единственный личный чат после нового /start. Для группы Chat ID задают явно.
3. **Независимый монитор.** Например, создайте в Healthchecks.io проверку с ожидаемым периодом 2 минуты и запасом 5 минут, подключите Telegram и сохраните секретный Ping URL. Дополнительно настройте внешнюю HTTPS-проверку https://loyalty.addwise.kz/health/ready. Ping подтверждает завершённый цикл мониторинга, а не финансовую приёмку.

Токены вводятся только в SSH-терминале установщика. Они хранятся в root-owned файлах 0600 в /etc/bonuspro-ops. Не помещайте их в аргументы команд, Git, скриншоты или сообщения.

## Установка

Из проверенного checkout в /home/ubuntu/bonuspro-auth-fix-5f54893c1894:

    sudo apt-get update && sudo apt-get install --no-install-recommends -y rclone

    sudo python3 -u /home/ubuntu/bonuspro-auth-fix-5f54893c1894/deploy/setup_operations.py --install --configure --enable

Установщик проверяет чистый Git checkout, копирует код в /usr/local/lib/bonuspro-ops и устанавливает systemd units. Таймеры исполняют root-owned копию. Параметр --source-revision принимает полный проверенный SHA.

Секреты не перезаписываются молча. Явная замена подключения создаёт новый защищённый файл и атомарно переключает конфигурацию. Операционная ошибка совместной настройки и проверки новых реквизитов восстанавливает прежнюю действительную конфигурацию. Частичные изменения, явно выбранные владельцем, сохраняются.

Если хранилища нет, можно подключить Telegram и мониторинг. Результат будет OPS_SETUP_PENDING. Таймер внешнего копирования включается после первой проверенной копии. Без независимого монитора и отдельной копии ключа полная готовность не подтверждается.

## Ключ восстановления

Установщик один раз создаёт /etc/bonuspro-ops/recovery_key. Он отличается от ключа токенов приложения и шифрует конфигурационный архив с ключами приложения.

Сохраните защищённую копию recovery_key вне VPS, например в менеджере паролей владельца. Подтверждение установщика является заявлением владельца, а не проверкой другого устройства. Ключ не выводится в журналы и не загружается в bucket открытым. Потеря VPS и единственного ключа делает восстановление конфигурации невозможным.

## Подтверждённая копия

Ежедневно около 03:00 UTC, с задержкой до 15 минут, задание:

1. Создаёт согласованный pg_dump и шифрует форматом BPBK0001.
2. Шифрует отдельный архив конфигурации, всех секретов приложения, Compose и версии образа.
3. Загружает ciphertext и контрольные суммы в уникальную папку bucket.
4. Скачивает точные объекты, сверяет размер и SHA-256.
5. Полностью аутентифицирует дамп до pg_restore; восстанавливает временную БД, проверяет схему и баланс проводок, удаляет временную БД.
6. Расшифровывает скачанный конфигурационный архив и сверяет содержимое без извлечения в рабочие каталоги.
7. Публикует manifest и backup-success.json только после успеха.

Сбой очистки временной БД — ошибка проверки. Неудачный запуск сохраняет подтверждение предыдущей копии. Удаление и ротация копий не выполняются.

У задания своя исключительная блокировка и общая блокировка изменения выпуска. Обновление ждёт завершения checkpoint; мониторинг приложения продолжает работать.

Ежедневное расписание допускает потерю изменений после последней успешной копии. Владелец согласует интервал, срок хранения и затраты. Более частое расписание задают systemd override после оценки базы. Оповещения о диске не заменяют политику хранения.

## Мониторинг

Таймер запускает проверку через минуту после завершения предыдущей. Проверяются контейнеры приложения/БД/пула, здоровье и версии, публичная HTTPS-готовность, свежесть обработки аккаунтов, ошибки API и задания, свободное место/inode, свежесть копии и результат службы/таймера копирования.

Инцидент открывается после трёх последовательных сбоев, восстановление — после двух успешных проверок. Telegram получает переходы, а продолжающиеся рабочие сбои — напоминание раз в 6 часов. Ошибки начальной настройки не создают повторных напоминаний.

Доставка требует успешного ответа Telegram. При потерянном подтверждении возможен повтор того же события. Состояние и повторы сохраняются после перезапуска.

Для планового обновления есть период ожидания до 30 минут; проверки диска и копий продолжаются. Потерю VPS или самого монитора обнаруживает независимый сервис по отсутствию Ping. Без внешнего сервиса локальное приложение об этом сообщить не сможет.

Передаются фиксированные русские описания и коды, агрегированные состояния. Данные покупателей, номера заказов, tenant ID, ошибки API и секретные URL не отправляются.

## Проверка без изменения финансов

    sudo python3 -E -s /usr/local/lib/bonuspro-ops/monitor_vps.py --check-only

Не отправляет Telegram/Ping, не пишет состояние инцидентов и не запускает обработку заказов.

    sudo python3 -E -s /usr/local/lib/bonuspro-ops/offsite_backup.py --check-config

Проверяет локальную конфигурацию без дампа или загрузок.

    sudo systemctl list-timers bonuspro-offsite-backup.timer bonuspro-monitor.timer --no-pager

Службы: bonuspro-offsite-backup.service и bonuspro-monitor.service. Наши команды выводят безопасные коды этапов; сторонние полные журналы могут содержать реквизиты.

## Значение результата

OPS_READY подтверждает проверку внешнего копирования/скачивания/восстановления, доставки Telegram, Ping, ключа и текущих технических проб. Это результат на момент проверки.

OPS_SETUP_PENDING называет незавершённый этап. Приложение продолжает работать; подключённый мониторинг сохраняется.

Поле independent_machine_restore_verified остаётся false: временная БД не является проведённой репетицией на другом VPS. CI отдельно проверяет шифрование, скачанные файлы и изолированное восстановление. Реальный bucket и уведомления подтверждаются после подключения реквизитов владельца.

Финансовая приёмка — по HANDOVER.md. Мониторинг и копии не заменяют бизнес-сценарии магазина.

## Хранилище у PS.kz

У владельца VPS используется PS.kz. Отдельную услугу можно подключить в том же кабинете:

1. Войдите в console.ps.kz и откройте «Объектное хранилище».
2. Создайте проект и выберите подходящий тариф хранения. Это отдельная услуга от диска VPS; проверьте стоимость перед заказом.
3. Создайте приватный контейнер с именем bonuspro-backups.
4. Создайте отдельного пользователя для копирования с доступом к этому контейнеру.
5. Сохраните его S3-реквизиты и API endpoint из кабинета. Для настройки нужен именно HTTPS S3 API, а не адрес публикации статического сайта.
6. Введите параметры через скрытые поля setup_operations.py. Проверка установки сама проверит загрузку и скачивание.

Источник: [PS.kz: начало работы с объектным хранилищем](https://docs.ps.kz/ru/cloud/object-storage/instructions/getting-started). Фактические endpoint, регион, тариф и права берутся из созданного проекта.
