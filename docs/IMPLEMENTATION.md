## Реализованный рабочий путь

1. Настройки ставок/история, привязка кошелька к контрагенту, версия правил заказа.
2. Сохранённый заказ REMAP -> расчёт -> атомарный резерв/план -> host UpdateRequest ->
   сохранение в МойСклад -> повторное серверное чтение -> списание.
3. Фоновая сверка новых заказов, оплат/отгрузок, начисление после обоих условий,
   восстановление подтверждённого списания после закрытия браузера.
4. Накопительные возвраты по строкам и отмена возвратов; пересчёт начисления/списания;
   административное решение без долга, повторная проверка исправленного заказа.
5. Предпросмотр сопоставленного CSV и атомарный импорт начальных остатков с аудитом.
6. Подтверждённая Vendor-активация, защита от гонки с Suspend, неизменный cutoff.
7. Явные разрешения сотрудников всего аккаунта и их отзыв перед финансовой записью.
8. Административное освобождение резерва отменённого исходного заказа без скидки,
   оплат и отгрузок. Поздняя старая метка создаёт расхождение.
9. Диагностика pending-возвратов, долгих резервов, dead jobs и задержки обработчика.

Безопасность: раздельные роли БД, FORCE RLS, составные tenant-FK,
неизменяемый сбалансированный журнал, Origin/Host/CSP, фиксированный REMAP host,
AES-GCM для токенов, одноразовые Vendor JWT, ограниченные сессии, секреты только на сервере.
Маршруты денег не принимают tenant/роль/автора или доказательство скидки из браузера.

## Что ещё не закрыто

**Программные и эксплуатационные ограничения:**
- Периодическая сверка без webhook-приёмника; масштабирование накопленной истории,
  очень поздняя индексация созданных заказов, общие квоты API и нагрузка ещё требуют доработки.
- Не поддержаны оплаты исключительно через invoiceout, НДС сверху и суммы скидок,
  которые нельзя точно представить шагом 0,01%. Неподдержанные случаи не списывают бонусы.
- Доставка должна быть service в МойСклад. Название товара не используется как классификатор.
- Отмена резерва активного/изменённого/оплаченного заказа не выполняется произвольно.
  Требуется восстановление проверяемого исходного состояния; нет атомарного compare-and-swap на стороне host.
- CSV-импорт готов для сопоставленного формата; реальный экспорт БонусПлюс и сверка дублей ещё не получены.
- Внешний мониторинг, независимый зашифрованный backup, его расписание/retention,
  очистка технической истории и процедуры ротации/восстановления ещё не настроены на VPS.

**Внешняя приёмка:**
- Установка/обновление/Resume/Suspend в настоящем МойСклад.
- Реальная покупка: скидка, оплата, отгрузка, частичный возврат, его отмена,
  закрытый браузер и два сотрудника.
- Проверка мержа строк/служебных полей UpdateRequest, округлений, тарифных прав API.
- Нагрузочная проверка имеющегося VPS и приёмка переноса остатков магазином.

Эти пункты не закрываются числом тестов. Утверждать «100% готово» нельзя.
