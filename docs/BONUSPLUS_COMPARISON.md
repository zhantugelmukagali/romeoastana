# Сценарии МойСклад: сопоставление с БонусПлюс

Сопоставление выполнено по публичной документации БонусПлюс 19.10.2026.
Цель выпуска БонусПро — бонусы, персональные скидки, клиенты и возвраты
в заказах МойСклад. Совпадение всех настроек сторонней платформы не заявляется.

## Рабочий сценарий

| Действие | БонусПлюс | БонусПро |
|---|---|---|
| Открыть заказ клиента | Баланс, условия, возможное списание и начисление | Баланс, персональная скидка, лимит и ожидаемое начисление в виджете |
| Назначить скидку клиенту | Процент связан с картой/статусом; возможен фиксированный статус | Администратор назначает процент непосредственно клиенту |
| Выбрать сумму бонусов | Сумму можно изменить до применения | Целая сумма в пределах баланса и лимита |
| Учесть обычную скидку | Внешние скидки передаются отдельно от скидок программы | Обычная скидка, персональная скидка и бонусы разделены в расчёте |
| Применить условия | Скидка отражается в позициях заказа | Абсолютные изменения позиций, затем проверка сохранённого документа |
| Сменить покупателя или состав | Результат требуется отменить/пересчитать | Связь с покупателем меняется до финансовой истории; финансовые изменения требуют проверки |
| Вернуть товар | Результат программы корректируется по покупке | Списанные и начисленные бонусы пересчитываются по исходной покупке; персональная скидка не становится бонусами |

Источники: [актуальное описание интеграции МойСклад](https://www.bonusplus.pro/integrations/moysklad/),
[карты и скидки](https://wiki.bonusplus.pro/crate_bonuscard),
[разделение скидок и бонусов в API](https://bonusplus.pro/api/Help/ResourceModel?modelName=ReceiptDiscount).

## Правила, которые нужно учитывать при приёмке

- В БонусПлюс момент продажи выбирается по документу. В этом выпуске БонусПро
  начисление выполняется после полной оплаты **и** полной отгрузки.
- БонусПро использует контрагента МойСклад как идентификатор бонусного счёта.
  Совпадение телефона не объединяет разных контрагентов автоматически.
- Доставка и услуги исключены по согласованному правилу магазина.
- Один бонус равен одному тенге; используются целые бонусы с округлением вниз,
  без срока действия.
- При недостатке бонусов для отмены начисления случай направляется
  администратору; автоматический отрицательный баланс запрещён.
- БонусПлюс поддерживает дополнительные правила карт. В БонусПро этого выпуска
  персональный процент задаётся клиенту, общие ставки начисления/списания —
  программе. Автоматические уровни карт здесь не имитируются.
- Публичная документация подтверждает возможность совмещения скидок и бонусов,
  но не фиксирует единственную арифметическую формулу для каждой интеграции.
  Правила БонусПро явно описаны в [инструкции персональных скидок](PERSONAL_DISCOUNTS.md).
