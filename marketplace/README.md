# БонусПро — материалы карточки МойСклад

Файлы для заполнения карточки зарегистрированного серверного решения. Перед отправкой проверьте установку, запуск обработки и контрольную продажу на публикуемой версии. Формат пакета не подтверждает работу сервера.

## Пакет для загрузки

Откройте успешный запуск **Marketplace package** в [GitHub Actions](https://github.com/zhantugelmukagali/romeoastana/actions/workflows/marketplace.yml), соответствующий выбранному коммиту, и скачайте артефакт **bonuspro-marketplace-package**. В нём находятся актуальный XML, описание, иконка и заново собранная инструкция.

| Поле в кабинете | Что использовать |
|---|---|
| Название | БонусПро |
| Псевдоним | Существующая карточка, appUid: bonuspro.romeoastana |
| Тип | Серверное решение |
| Описание | Сам текст `description.txt`, без ссылки на файл |
| Дескриптор | Полный текст `descriptor-widget.xml` |
| Встроенная инструкция | `bonuspro-manual.zip` из артефакта; не распаковывать |
| Внешняя инструкция | https://github.com/zhantugelmukagali/romeoastana/blob/bonuspro/rebuild/marketplace/GUIDE.md |
| Иконка | `bonuspro-icon.svg` |
| Поддержка | zhantugelmukagali@gmail.com |
| Видео и изображения | Необязательны; используйте только реальные материалы продукта |

`descriptor-draft.xml`, `description-draft.txt` и сохранённый ранее ZIP в Git оставлены для истории. Их не используют для итоговой загрузки. Артефакт всегда пересобирает ZIP из текущего `manual/index.html`, а проверка сравнивает содержимое архива с исходником.

Локальная сборка: `python3 marketplace/build_manual.py`, затем `python3 scripts/check_marketplace.py` в среде с lxml. Скрипт сборки обновляет локальный ZIP; двоичный файл не нужно добавлять в коммит.

## Дескриптор и версия

- `endpointBase`: https://loyalty.addwise.kz, без добавления пути Vendor API.
- Главное окно: **/admin**; виджет заказа: **/widget**.
- Схема дескриптора v2. Авторизация через user-context, без contextKey в URL.
- Сервер читает документы; форму заказа меняет виджет под правами сотрудника. Дескриптор разрешает работу со своим служебным полем и собственными уведомлениями.
- Права общего администрирования и серверного изменения документов не запрашиваются. Кассовый loyaltyApi в этот выпуск не входит.

Основная ветка `bonuspro/rebuild` требует схему **0018**, содержит уведомления об изменениях и пул нескольких аккаунтов (профиль `marketplace`). Для перехода с совместимой 0015 используйте проверенный deploy/finish_marketplace.py. Он проверяет восстановление и сохранность истории перед мостом схем. Подтверждение запуска пула на VPS и финансовой приёмки фиксируется отдельно от CI.

Образы веток нельзя менять между схемами без отдельного обновления. Проверка готовности и реального заказа описана в [передаче магазину](../docs/HANDOVER.md).

## Перед отправкой на модерацию

1. Сверьте сохранённый XML в кабинете с файлом из артефакта.
2. Завершите подключение в БонусПро: правила, виджет, запуск программы и автоматическая обработка. Выполните контрольную покупку, списание и возврат на установленном образе.
3. Заполните почту уведомлений в реквизитах разработчика и проверьте контакты в карточке.
4. Проверьте условия выбранного способа распространения. Для полностью бесплатного публичного решения требуется предварительное согласование с МойСклад; его наличие этим репозиторием не подтверждено.
5. Сохраните карточку и отправьте на модерацию после проверки материалов и рабочего сценария. Во время рассмотрения редактирование карточки ограничено; отправка не означает публикацию в тот же день.

Секретный ключ не включают в XML, описание, инструкцию или архив. Идентификаторы приложения: [REGISTERED_APP.md](../docs/REGISTERED_APP.md).
