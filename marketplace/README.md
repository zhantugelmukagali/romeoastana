# БонусПро — заполнение карточки МойСклад

Пакет для **сохранения черновика**, не для отправки готового продукта на модерацию.
Состояние кода: [IMPLEMENTATION.md](../docs/IMPLEMENTATION.md).
Дескриптор не разворачивает приложение и не подтверждает работу URL на VPS.

## Поля формы

| Поле | Значение / действие |
|---|---|
| Название | БонусПро |
| Псевдоним | bonuspro_addwise |
| Ссылка на внешний сайт с инструкцией | https://github.com/zhantugelmukagali/romeoastana/blob/bonuspro/rebuild/marketplace/GUIDE.md |
| Встроенная инструкция | Загрузить bonuspro-manual.zip из этой папки |
| Иконка | Загрузить bonuspro-icon.svg из этой папки |

| Изображения | Оставить пустым — необязательно. Перед выпуском добавить реальные скриншоты |
| Описание | Скопировать description-draft.txt |
| Тип решения | Серверное |
| Счётчик Яндекс Метрики | Оставить пустым, если своего счётчика нет |

| Действие | Сохранить черновик |

Псевдоним нельзя изменить после создания. Его доступность проверяет МойСклад при сохранении.
Ссылка на GitHub — доступная инструкция для черновика; перед публичным выпуском
инструкцию и описание нужно обновить по реально работающим сценариям.
ZIP уже содержит index.html в корне. Его не нужно распаковывать перед загрузкой в МойСклад.
Для скачивания файла с GitHub откройте его и используйте Download raw file.

## Что делает дескриптор

- Схема v2, тип ServerApplication.
- endpointBase — https://loyalty.addwise.kz, **без** суффикса /api/moysklad/vendor/1.0.
  МойСклад добавляет путь /api/moysklad/vendor/1.0/apps/{appId}/{accountId}.
- Главное окно /admin соответствует маршруту новой реализации.
- Авторизация через одноразовый user-context; contextKey в URL выключен.
- custom-права: чтение заказов, отгрузок, возвратов, оплат, контрагентов, юрлиц и валют.
- Нет административных прав, прав изменения документов и неподдерживаемых протоколов.
- Нет блока loyaltyApi: обработчики Кассы МойСклад не реализованы.
- Нет widgets: в текущей реализации ещё нет рабочего виджета заказа.

Домен ранее обслуживал пилот. Новая реализация и её /admin/Vendor API пока не
подтверждены на этом домене. Сохранить карточку можно до развертывания; устанавливать
её и ожидать рабочую программу сейчас нельзя.

Добавление widgets/document.customerorder.edit и прав изменения customerOrder
выполняется вместе с готовым, проверенным обработчиком списания. После расширения
прав уже установленный черновик потребуется переустановить: права фиксируются
на момент установки.

## После сохранения

Открыть вкладку «Учетные данные решения». appId и appUid можно передать разработчику.
Secret Key настраивается на сервере через защищённый файл; не помещать в чат, GitHub,
описание или XML. Затем развернуть новую версию отдельно от пилота и проверить её
на привязанном аккаунте разработчика. Не отправлять на модерацию, пока не закрыты
блокирующие задачи в IMPLEMENTATION.md.

Контакт поддержки владелец добавляет самостоятельно перед публикацией.
Для уведомлений о модерации необходима электронная почта в реквизитах разработчика.
Планируется публичный каталог: при подаче на модерацию не выбирать «Приватное решение» —
по документации режим распространения после модерации изменить нельзя.

## Яндекс Метрика

Это аналитика посещений и установок карточки, а не требование для работы бонусов.
Если счётчик уже есть, в поле вставляется его настоящий числовой ID, не код JavaScript.
Если нужен новый — создать его в https://metrika.yandex.ru/ и добавить цели типа
«JavaScript-событие» со следующими идентификаторами:

| Назначение | Идентификатор |
|---|---|
| Открытие внутренней карточки | open_app |
| Установка | install_app |
| Открытие главного окна | go_to_app |
| Удаление | uninstall_app |
| Открытие внешней карточки | external_app_page_view |
| Кнопка «Попробовать» | external_try_click |
| Регистрация с витрины | external_registration_click |
| Кнопка существующего аккаунта | external_login_click |

Отсутствующий ID не заменять нулём или произвольным числом. Инструкции по бонусам
не требуют Метрики; счётчик можно настроить отдельным шагом.
